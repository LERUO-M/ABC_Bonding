# Compile-on-contract-change

This repo (ABC_Bonding) deploys contracts via Hardhat (`scripts/deployAllAndVerify.js`,
`scripts/startAll.js`) and has a hand-written frontend ABI file
(`frontend/src/abis.ts`) that is **not** auto-generated.

## Rule

**Every time you (the AI) create or modify a `.sol` file under `contracts/`, immediately run:**

```bash
npx hardhat compile
```

Do this as the last step of the same turn you touched the contract, before moving on to other
work, and before telling the user the change is done. Treat a failing compile as blocking — fix
it before considering the contract edit complete.

## Why this matters

- `hardhat run` (used by `deployAllAndVerify.js`) does auto-compile before running, but relying on
  that alone has caused stale-bytecode bugs in this repo (e.g. deploying old bytecode after a
  branch switch, producing `Error: Transaction reverted without a reason string` /
  `<unrecognized-selector>` errors on every contract call from the frontend).
- Running `hardhat compile` explicitly and immediately catches signature/type errors right away,
  with a clear compiler error, instead of a confusing runtime revert much later during
  deploy/frontend testing.

## Out of scope (do not attempt to automate)

- `frontend/src/abis.ts` is a curated, hand-maintained subset of each contract's ABI (only the
  functions actually used by the UI). It is **not** regenerated by `hardhat compile` or by this
  skill. If a contract function's name, parameters, or return types change, you must manually
  update the corresponding entries in `frontend/src/abis.ts` to match — call this out explicitly
  to the user when it applies.
- If the user (not the AI) edits a `.sol` file directly, this skill does not apply — they are
  responsible for compiling themselves before deploying.
